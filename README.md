# Task Management REST API

Реализация REST API для управления задачами (To-Do списком) на языке Go. Проект разработан в рамках учебного домашнего задания с акцентом на чистую архитектуру, потокобезопасность и полное тестовое покрытие.

## Основные возможности
* **REST API:** Реализация 5 обязательных эндпоинтов для CRUD-операций над задачами.
* **Потокобезопасность:** Безопасная параллельная работа с данными в памяти (`sync.RWMutex`).
* **Валидация данных:** Строгая проверка входящих JSON-документов, очистка пробелов в строках и валидация ID.
* **Логирование:** Централизованное промежуточное ПО (Middleware) для логирования входящих HTTP-запросов.
* **Диагностика:** Наличие эндпоинта `/health` для проверки работоспособности сервиса.
* **Тестирование:** Интеграционные тесты для проверки поведения системы в различных сценариях.

## Архитектура проекта
Проект организован в соответствии с лучшими практиками Go-разработки:
* `cmd/server/main.go` — точка входа, инициализация зависимостей и запуск HTTP-сервера.
* `internal/models/` — описание доменных моделей данных (структура `Task`).
* `internal/storage/` — абстракция хранилища (`Storage` интерфейс) и его потокобезопасная реализация в памяти (`MemoryStorage`).
* `internal/handlers/` — HTTP-обработчики (Handlers), валидация запросов, маршрутизация и Middleware.

## Требования для запуска
* Установленный Go версии **1.20** или выше.

## Инструкция по запуску

### 1. Клонирование репозитория
```bash
git clone https://github.com
cd greekpontos-REST-API
```

### 2. Запуск сервера
Сервер по умолчанию запускается на порту `:8080`.
```bash
go run cmd/server/main.go
```

### 3. Запуск автоматизированных тестов
Для проверки работоспособности и отсутствия состояний гонки (data races) выполните:
```bash
go test -v -race ./...
```

## Документация API

Единый формат ответа при возникновении ошибок:
```json
{
  "error": "Описание ошибки для клиента"
}
```

### Доступные эндпоинты

| Метод  | Эндпоинт      | Описание | Ожидаемый статус (Успех) | Ожидаемый статус (Ошибка) |
|--------|---------------|----------|--------------------------|---------------------------|
| `GET`  | `/tasks`      | Получить список всех задач | `200 OK` | `500 Internal Server Error` |
| `POST` | `/tasks`      | Создать новую задачу | `201 Created` | `400 Bad Request` |
| `GET`  | `/tasks/{id}` | Получить задачу по ID | `200 OK` | `404 Not Found`, `400 Bad Request` |
| `PUT`  | `/tasks/{id}` | Обновить существующую задачу | `200 OK` | `404 Not Found`, `400 Bad Request` |
| `DELETE`| `/tasks/{id}`| Удалить задачу по ID | `204 No Content` | `404 Not Found`, `400 Bad Request` |
| `GET`  | `/health`     | Проверить состояние сервера | `200 OK` | `405 Method Not Allowed` |

*Детальные примеры запросов и ответов (включая негативные сценарии) для ручного тестирования находятся в файле [manual-tests.md](manual-tests.md).*
